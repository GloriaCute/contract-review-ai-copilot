# 软件采购合同审核规则包 0.1

## 规则包定位

本规则包面向“我方作为采购方，向外部供应商采购软件、信息系统及配套部署实施服务”的合同初审场景。它把企业审核关注点拆成付款、交付验收、责任与补救、保密披露四个事实领域，共 8 条规则，帮助审核人员发现与当前模拟企业规则不一致、信息不足或前后矛盾的事项，并回到合同原文复核。

规则包输出的是企业规则匹配结果，不提供法律意见或合同可签署结论。规则中的阈值、例外和处理要求属于本项目的模拟企业规则，不代表行业统一标准或法律要求。

## 状态与优先级体系

每条规则同时输出两个相互独立的维度：

- **审核状态**：符合、偏离、缺失、冲突、无法判断。
- **处理优先级**：必须处理、建议关注、一般提示、无需处理。

“缺失”表示合同没有出现规则要求的信息；“无法判断”表示已有相关表述，但内容含糊，或结论依赖当前未获得的相关附件等材料。两者分开，可以区分合同确实未约定与已有信息不足以形成确定判断。

“冲突”表示合同不同位置的相关事实互相矛盾，需要同时保留冲突证据并交由人工澄清；它不同于事实已经明确、但不符合标准规则或进入例外情形的普通“偏离”。处理优先级表示企业审核工作流中的处置顺序，不是法律风险等级，也不评价条款是否合法、公平或有效。

## 8 条规则总览

| 规则 | 业务目标 | 主要判断点 | 典型异常 |
|---|---|---|---|
| **P1 高比例预付款保护** | 控制高比例预付款敞口 | 交付前付款比例是否超过 40%，超出时是否有对应保护或已确认例外 | 高比例预付款无保护；保护安排含糊；比例事实冲突 |
| **P2 付款节点完整并关联履约结果** | 让主要价款支付可识别、可验证 | 节点金额或比例、触发条件、付款期限是否完整；非预付款是否关联明确履约结果 | 节点缺项、价款不闭合、仅凭发票或日期付款、付款计划附件未获得 |
| **A1 交付期限明确** | 确保核心交付时间可执行 | 是否有固定日期，或具备数字、单位和明确起算点的可计算期限 | 仅写“尽快”；期限缺失；同一交付事项期限矛盾 |
| **A2 验收依据和通过条件明确** | 让验收结论有具体、可验证的基础 | 是否有可识别的验收依据、通过条件及一致的指标 | 仅写“达到要求”；只以主观满意为准；验收标准附件未获得 |
| **A3 验收流程和时限明确** | 明确验收如何启动和完成 | 验收触发、验收或异议期限是否清楚；是否存在采购方沉默即视为验收通过的安排 | 流程期限缺失或含糊；触发点不明；逾期未异议即自动通过 |
| **W1 关键履约义务对应违约或补救机制** | 确认关键供应方义务具有明确后果或补救 | 交付、部署或上线失败，以及验收不合格后的整改义务，是否对应专项或明确通用机制 | 关键义务无机制；只有“承担相应责任”等笼统表述；与责任或补救机制直接相关的附件未获得 |
| **W2 双方可比较责任差异** | 客观呈现可机械比较的迟延责任差异 | 比较采购方逾期付款与供应方逾期交付责任的比例、计价单位或责任基数、责任上限或无限责任、触发条件和宽限安排 | 仅有采购方责任；计算基础不可比；采购方责任在冻结维度上明确更重 |
| **C1 保密披露边界** | 控制采购方保密信息向外部第三方披露 | 一般第三方披露是否以采购方事先书面同意为前提，是否仅保留依法披露例外 | 顾问、关联方等可未经同意接收信息；披露条件含糊；多处约定冲突 |

## 典型规则设计逻辑

规则先判断事实是否充分，再判断是否符合标准，并把多个命中原因聚合到一张规则结果中。例如，P1 的 40% 只是一项模拟企业参考阈值：超过阈值后才继续检查保护措施或例外审批，不能表述为违法或行业上限。A2 与 A3 刻意分工，前者检查“依据什么、怎样算通过”，后者检查“如何验收、何时反馈”。W1 只检查当前冻结的供应方交付及验收整改义务是否有机制；W2 只比较双方迟延履行责任，不扩展到保密、知识产权、提前解除或复杂赔偿，也不评价公平性。

## 模型与规则边界

LLM 只负责理解合同语言，提取规则所需的原子事实及其证据引用，不直接生成最终审核状态或处理优先级。比例计算、期限分类、字段完整性、责任配对、数值比较和冲突聚合由 TypeScript 确定性规则完成。证据引用必须包含真实 `blockId` 与对应文本块中的逐字 `quote`，无效引用会被拒绝。这样的分层让事实、规则判断和人工决定保持可解释、可追溯。

## 当前适用边界

当前版本只处理文字型 DOCX 主合同，不支持扫描件 OCR、多附件上传或其他合同类型。外部附件未实际获得时，不假定附件内容存在。规则包不判断合同是否合法、是否公平、是否一定可以签署，也不自动修改合同或生成谈判方案；最终业务接受、例外批准和法律判断仍由人工负责。

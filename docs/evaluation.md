# 合同审核助手 0.1：产品级评测说明

## 评测目标

本项目的评测不只回答“模型能否读懂合同”，而是验证一条完整产品链路：DOCX 解析、原子事实提取、TypeScript 确定性规则、证据定位与不确定性处理。评测集必须在运行前冻结，因为输入、预期状态、处理优先级和证据要求若随输出修改，就无法判断迭代是否真正改善，也无法定位失败来自解析、事实、规则还是证据层。

## 评测集设计

评测集由 16 份人工合成的软件采购合同组成，统一执行 P1、P2、A1、A2、A3、W1、W2、C1 八条规则。案例既包含八规则全部正常的基准合同，也覆盖高预付款无保护、付款未关联履约、模糊或冲突的交付期限、验收标准缺失或不可验证、默示验收、验收期限缺失、未经同意向顾问披露、保密边界不明、交付义务缺少机制、双方迟延责任差异、验收附件未获得及多风险组合。所有合同均为合成材料，不包含真实客户数据。

## 验证维度

每个案例分别检查：文档是否可稳定解析；八条规则的状态与处理优先级是否符合冻结预期；目标异常是否命中且正常规则不被误报；结构是否通过 Schema 约束；每条证据的 `blockId` 是否存在、`quote` 是否为对应文本块的 exact quote；付款、交付验收、责任补救和保密事实是否保持领域隔离。网络重试与业务失败分开记录，避免用重试掩盖结构、证据或规则问题。

## 最终结果

- 16 / 16 份合成合同完成正式审核。
- 128 / 128 个规则结果（16 个案例 × 8 条规则）的状态与处理优先级符合冻结预期。
- 26 / 26 个定向目标规则结果的状态与处理优先级符合冻结预期。
- 结构校验失败 0；`blockId` / exact `quote` 证据校验失败 0；事实域串线 0。
- 冻结评测运行中应用级重试 0。

在 16 个冻结的人工合成产品评测案例中，最终未发现业务结论错误、证据校验失败或事实域串线。

## 典型问题：E15

E15“验收标准附件缺失”首轮暴露了 W1 跨域附件污染：责任与补救事实组将 A2 的“技术验收标准”附件标记为 W1 相关，确定性规则又无条件信任该标记，使 W1 被误判为“无法判断 / 必须处理”。评测将问题定位到规则输入边界，而非模型结构或证据格式。修复没有改动 Prompt 或 Schema，而是在 W1 输入处增加确定性附件业务相关性过滤，使单纯验收标准附件只影响对应验收规则。回归复验后，A2 保持“无法判断 / 必须处理”，W1 恢复“符合 / 无需处理”，且不再引用该验收附件证据。

## 评测边界

该结果只说明当前冻结规则、冻结合成材料与当次产品链路的匹配情况。它不覆盖真实世界合同的无限表达、扫描件 OCR、多附件或其他合同类型。这不是对真实合同准确率的声明，也不代表生产环境 SLA。评测结果也不构成法律意见或合同可签署结论。
